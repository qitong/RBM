# 合成逾期同意率判断

对应 GitHub Issue #8。启曈在统筹 Item #83 事件 e598 批准的范围只包括这一条。本文是 PRD 和功能清单，不是临床规则。

## 用户场景

质量负责人打开阈值页，查看虚构研究 `SYN-FICTION-MIST-001` 的一条逾期签署比例。已批准计划里这条规则的单位是百分比，预警 4，行动 9。页面告诉他当前合成值落在正常、预警还是行动。

## 输入和输出

输入是两个分开的东西：

- 已批准 CtQ 计划里的候选 `KRI-01`：预警界限、行动界限、单位。
- 合成观察值：仓库里的常数 9，表示这条虚构比例，不是从受试者算出来的。

输出是「正常」「预警」或「行动」，并写明单位是百分比。下面任一情况只输出失败，不给等级：没有观察值；计划里没有 `KRI-01`；单位不是百分比；界限不是大于等于 0 且预警小于行动；数值不是大于等于 0 的有限数。失败时不改读静态 JSON，也不改用标准差预设。

比较时包含等号：小于 4 为正常；等于 4，或大于 4 且小于 9，为预警；等于 9 或大于 9 为行动。负数不取绝对值。

## 边界

CtQ 计划文件和 RBQM 阈值版本仍然是两套存储。这条判断只读 CtQ 已批准计划。4 和 9 不写入知情同意的 SD 滑块。不实现阈值同屏，也不把中心信号升成研究级候选。不读取真实方案或患者资料。

## 功能清单

1. 判断函数：只接受这一条百分比规则，落实等号和失败状态。
2. 阈值页上的一张合成卡片：计划读失败或规则不合格时显示失败，不显示等级。
3. 测试：3.9 正常，4 预警，9 行动；缺值、错误单位、把百分比当 SD 都不给出百分比等级。
4. 黑盒：命令是在 `frontend` 里运行 `npm run blackbox`。它启动本机 API，用公开的 `POST /api/ctq/extract`、`POST /api/ctq/drafts/{id}/approve` 和 `GET /api/ctq/active`，再经阈值页使用的判断函数核对 3.9、4 和 9。页面卡片本身核对合成值 9 的「行动」，以及缺计划和错研究时的失败。4 和 9 是这次批准请求里写下的界限，不是写死在页面里的固定生效值。
