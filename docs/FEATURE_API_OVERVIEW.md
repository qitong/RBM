## 产品速览

`main` 已有一条演示流程：

打开风险相关页面。Pages 上没有后端，直接显示包进前端的静态 JSON。本机启动 FastAPI 后才返回模拟中心、预警、CAPA；后端失败时前端同样改读静态 JSON。用户看到的回退数据不是一条明确的业务错误，也不能当作已批准的监测决定。

PR #3 尚未合并，多一条流程：

虚构方案文本 → 提取候选 → 人工批准或驳回 → 本机文件保存版本 → 预警页读取已批准预设。成功时候选保持未生效，只有批准版本改变预设。提取失败应返回错误，不应悄悄换成静态示例。回滚把生效指针移回上一已批准版本。复核指出：百分比与标准差尚未分开、批准后判断要刷新才更新、浏览器旧配置可能漏掉已批准类别。这三处未修好前，不把「批准值已可靠驱动判断」写成已完成。

## 鉴权与数据边界

无鉴权。Pages 上的前端演示是公开的。FastAPI 只在本机启动后可访问，同样没有登录或令牌。批准请求中的姓名字段不是可靠身份认证。

`main` 使用仓库内模拟数据和静态回退，不是真实试验数据。PR #3 只接受带虚构研究编号的合成文本。真实方案正文、受试者资料、桌面未提交文件和外部模型都不进入这条链路。Claude 提取技能仍是待决，没有迁入。

## Agent 可用能力卡

### 读取模拟风险页

用途：查看演示用的中心风险、预警和 CAPA。调用入口：Pages 或本地前端的页面路由。只读 HTTP（如 `GET /api/sites`）只有本机启动 FastAPI 后才存在。最小输入：无。主要输出：页面；本机后端可用时还有模拟 JSON。失败状态：后端没启动或失败时，前端改显示包内静态 JSON。权限或前提：无鉴权。证据：`main` 的 `backend/src/api/main.py` 与只构建前端的 Pages 工作流。Agent 可以打开 Pages 上的演示页，不能凭该链接调用后端。这些数据不是已批准的监测规则。

### 从虚构方案得到候选

用途：把完全虚构的方案文本拆成关键数据、CtQ、KRI、QTL 候选。调用入口：仅在 PR #3 的本地前端 `/ctq-plan`，以及本机启动该分支 FastAPI 后的 `POST /api/ctq/extract`。最小输入：含虚构研究编号的合成纯文本。主要输出：未批准草稿和来源摘录。失败状态：格式不对时返回错误码，不返回静态计划。权限或前提：无鉴权；分支未合并。证据：PR #3 的 `backend/src/api/ctq_routes.py`。Pages 和 `main` 上都没有这个入口。

### 批准后读取生效计划

用途：人工批准后读取当前版本，或回滚到上一版。调用入口：仅 PR #3 的 approve、rollback、`GET /api/ctq/active`。最小输入：草稿号、批准人和每条候选的接受与否。主要输出：版本号和已接受规则。失败状态：没有上一版时回滚失败，生效指针不变。权限或前提：必须有单独的人工批准动作。批准人字段没有身份校验，不能把它当成已认证的签署。证据：Issue #2 与 PR #3。判断预设的单位同步和刷新仍在修复，不能当成已经可靠。Pages 上不存在这些接口。
