# qitong/RBM 功能与 API 概览

核对时间：2026-11-24 22:30（Asia/Shanghai）。基线是 GitHub `main` `a9ff264`（2026-11-24T14:18:18Z，合并 PR #10）。PR #3、PR #5、PR #6、PR #7、PR #9、PR #10 都已合并。本文记录合成演示的发布条件。它不是临床系统，也不是监管符合性说明。

## 一眼摘要

一句话：质量负责人在合成数据上查看中心和研究级风险，用虚构方案生成监测规则候选，人工批准后，标准差类规则才会改预警用的预设。虚构研究的一条逾期签署比例会按已批准的百分比界限判断。

输入 → 输出：打开 Pages 得到合成前端演示。只读 HTTP 要本机另启 FastAPI。`/ctq-plan` 接受虚构方案文本，给出未生效候选；批准后得到一版本机监测计划。研究级和中心级风险可以按证据从发现走到关闭。

验收与边界：Pages 只发布合成前端，而且只在名为 CI 的工作流对当时的 `main` 完成一次 push、并且 backend 与 frontend 两个作业都成功之后。失败、取消、跳过、没有作业，或这个提交已经不再是 `main`，都不会发布。部署工作流本身不跑测试。PR 上的检查不发布。手动触发也要先通过同一道校验。全部是合成或模拟数据。这不是临床发布。回滚是还原该合并提交；还原出来的新提交仍要自己的 main CI 全部成功，Pages 才会回到上一版前端。

## 产品速览

`main` 上现在有两条合成流程。

第一条是风险演示。打开风险、任务、CAPA、审计、阈值和中心对比。研究级 QTL 管全研究的合成容忍限，中心级 KRI 管单个合成中心。关闭前必须有根因、责任人和有效性复核；缺任何一项时状态不变，并返回错误。默认情况下，这套风险接口失败不会改读静态 JSON。只有显式打开 `VITE_RBQM_STATIC_FALLBACK=1` 时，才使用带 `fallbackActive: true` 的离线合成文件。

第二条是监测计划。虚构方案文本 → 提取候选 → 人工批准或驳回 → 本机文件保存版本 → 标准差类已批准规则写入预警用的预设。成功时候选保持未生效。提取失败应返回错误，不应悄悄换成静态示例。回滚把生效指针移回上一已批准版本。百分比规则保留自己的单位，不会写成标准差。阈值页对虚构研究 `SYN-FICTION-MIST-001` 的候选 `KRI-01` 使用单独判断。方案里的建议值是预警 4、行动 9，审批人可以写成别的数；页面用的是实际批准下来的界限，不是把 4 和 9 当成固定生效值。合成观察值是 9，单位是百分比；等于当时批准的界限即算越界。计划读失败、单位不对、研究编号不对或没有数值时只显示失败。`checkApprovedMetric` 仍会取绝对值且不校验单位，页面不调用它，它不是这条百分比规则的安全入口。预警页对单位为 SD 的合成风险使用标准差预设；单位不是 SD 时，严重程度来自该合成风险自己带的级别，不是来自那条百分比界限。

CtQ 计划文件和 RBQM 阈值版本是两套存储，本概览不把它们当成已经合并。

旧复核里的三处问题已经在合并前的 PR #3 里修好：百分比不再当成标准差预设、批准后判断会随版本更新、浏览器里缺了的类别会按已批准的标准差规则补回。这三处不再写成未完成。上述那一条逾期签署比例已经接到阈值页。

## 入口与运行状态

页面入口：`/dashboard`、`/alerts`、`/thresholds`、`/sites/:siteId`、`/benchmark`、`/correlation`、`/investigators`、`/forecast/:siteId`、`/capa`、`/tasks`、`/subjects`、`/data-quality`、`/risk-forecast`、`/audit`、`/reports`、`/ctq-plan`。

本机另行启动 FastAPI 后，才有模拟读取接口，例如 `/api/health`、`/api/sites`、`/api/benchmark`、`/api/correlation`、`/api/investigators`、`/api/capa`。GitHub Pages 只托管构建后的前端。Agent 不能凭 Pages 链接调用这些 HTTP 接口。

监测计划接口同样只在本机 FastAPI 上：`POST /api/ctq/extract`、`POST /api/ctq/drafts/{id}/approve`、`POST /api/ctq/drafts/{id}/reject`、`POST /api/ctq/active/rollback`、`GET /api/ctq/active`、`GET /api/ctq/versions`。approve 和 rollback 是无鉴权的演示写操作。请求里的批准人只是填写的字段，不是身份认证。候选不会自动生效。

风险闭环接口也只在本机 FastAPI 上，包括 `/api/rbqm/study`、`/api/rbqm/risks`、风险状态迁移、任务、行动、CAPA、审计、阈值版本和中心对比。这些写操作同样没有登录。

较老的演示读取在后端不可用时仍可能改读包进前端的静态 JSON。`/api/ctq/*` 和 `/api/rbqm/*` 不在这条静默回退里。

本地桌面克隆有未提交文件，不作为开发或文档事实来源。

CI：`pull_request` 和 push `main` 都跑后端 pytest，以及前端的安装、tsc、vitest 和 `npm run build`。其中 `npm run blackbox` 会启动本机 API，从公开的 `/api/ctq/active` 和阈值页卡片核对合成逾期签署比例。没有检查结果不是通过。GitHub Pages 不再跟着 push 同时启动。它等到这次 CI 结束，核对工作流结论和每一个作业都是成功，并且提交仍等于当时的 `main`，才构建并发布合成前端。手动触发走同一道核对。

已部署：这次发布条件改动之前，https://qitong.github.io/RBM/ 对应 `main` `a9ff264`，环境 `github-pages`，部署成功于 2026-11-24T14:19:09Z。它是合成前端演示，没有 FastAPI，不是临床监测上线。阈值页上的百分比卡片在 Pages 读不到已批准计划，因此只显示无法判断，不会在站点上给出等级。

## 鉴权与数据边界

无鉴权。Pages 上的前端演示是公开的。FastAPI 只在本机启动后可访问，同样没有登录或令牌。批准请求中的姓名字段不是可靠身份认证。

仓库使用模拟数据和带虚构研究编号的合成文本，不是真实试验数据。真实方案正文、受试者资料、桌面未提交文件和外部模型都不进入这条链路。Claude 提取技能没有迁入。

## Agent 可用能力卡

### 读取合成风险页

用途：查看演示用的中心风险、研究级信号、预警、任务、CAPA 和审计。调用入口：Pages 或本地前端的页面路由。只读 HTTP 只有本机启动 FastAPI 后才存在。最小输入：无。主要输出：页面；本机后端可用时还有合成 JSON。失败状态：风险接口失败时显示错误，不改读静态 JSON，除非显式打开离线合成回退。权限或前提：无鉴权。证据：`main` 的 `backend/src/api/rbqm_routes.py` 与只构建前端的 Pages 工作流。这些数据不是已批准的真实监测规则。

### 从虚构方案得到候选

用途：把完全虚构的方案文本拆成关键数据、CtQ、KRI、QTL 候选。调用入口：`/ctq-plan`，以及本机 FastAPI 的 `POST /api/ctq/extract`。最小输入：含虚构研究编号的合成纯文本。主要输出：未批准草稿和来源摘录。失败状态：格式不对时返回错误码，不返回静态计划。权限或前提：无鉴权。证据：`backend/src/api/ctq_routes.py`。Pages 上没有这个 HTTP 入口。

### 批准后读取生效计划

用途：人工批准后读取当前版本，或回滚到上一版。调用入口：approve、rollback、`GET /api/ctq/active`。最小输入：草稿号、批准人和每条候选的接受与否。主要输出：版本号和已接受规则。失败状态：没有上一版时回滚失败，生效指针不变。权限或前提：必须有单独的人工批准动作。批准人字段没有身份校验。证据：已合并的 PR #3 和 PR #9。标准差类规则会改预设。百分比判断只覆盖那一条合成逾期签署比例，而且要本机 FastAPI 读到已批准计划；Pages 上没有这些 HTTP 接口。`checkApprovedMetric` 不是这条规则的安全入口。

### 按证据关闭一条合成风险

用途：把一条合成风险从发现走到关闭。调用入口：本机 `POST /api/rbqm/risks/{id}/transitions`。最小输入：目标状态、操作者，以及该步要求的根因、责任人或有效性复核。主要输出：新状态和审计记录。失败状态：缺证据时返回错误，状态保持不变。权限或前提：无鉴权，数据必须是合成的。证据：已合并的 PR #6，`docs/RBQM_STUDY_AND_SITE_STRATEGIES.md`。
